# 規則書應用改版設計 — 從資料列表變成一本書

> 定案日期：2026-09-21
> 影響範圍：`app/` 全部前端、`app/src-tauri/src/db.rs` 查詢層
> 前置狀態：Phase 3 已完成搜尋／篩選／專長詳情，本文件取代那一版介面

## 為什麼要改

現在的介面是「一個扁平的專長清單 + 篩選器」。612 條專長混在一起，
要看法師有哪些學派專長，得先篩分組再篩分類，而且看不出學派之間的從屬關係。

但原始試算表本來就是分章的 —— 31 張工作表，法師學派專精是一張、術士是一張。
使用者腦中的模型是「翻到法師那一章」，不是「對全書下篩選條件」。
介面應該長得像那本書，而不是像它背後的資料庫。

**這次改版只動呈現層。** 資料管線、schema、勘誤機制完全不變，
資料庫仍是唯讀的建置產物。

## 一、導覽骨架：兩層章節

頂部第一排是**章節**，選定後第二排才是該章節的**頁籤**。

| 章節 | 頁籤 | 資料來源 |
|---|---|---|
| 創角規則 | 創角流程、施法者、戰鬥流程、FATE 特規 | `rule_text` 4 張表（54 段）＋ 2 張 `ref_table` |
| 專長 | 基本 35、一般 103、製作 52、超魔 16、高級 18、傳奇 27 | `feat` 非 class 的 6 個 `feat_group` |
| 職業 | 法師、術士、牧師、德魯伊、吟遊詩人、武僧、Warlock、賢者、奈瑟瑞爾奧術師、咒火使者、聖騎士、魔法舞者、魔射手、神掌門（14 個） | `class_path` 96 條、`feat` 361 條、`class_trait` 27 條、`invocation` 58 條 |
| 物品 | 一般詞綴 118、高階詞綴 37、永恆聖器 20、素材與素材詞綴、價格表、詞綴分布 | `affix` / `material` / `ref_table` / `affix_distribution` |
| 種族 | （單頁，13 個種族） | `race` / `race_attr_modifier` |
| 附錄 | 世界觀、大陸簡史、Patch note、狩獵任務、對照表總覽、CP 試算、勘誤清單 | `rule_text` / `ref_table` / `errata` |

**為什麼不用扁平的 Excel 式頁籤。** 攤平就是約 30 個頁籤，1280px 寬度下必然要橫向捲動，
而且會把「創角須知」跟「高階詞綴」放在同一個視覺層級 —— 那不是這本書的結構。

**章節與頁籤都保留原表順序**，不重新排序。使用者拿著 xlsx 對照時找得到同一個位置。

## 二、章節內的版面

以職業章節的法師頁為例（其他章節同構）：

```
┌ 創角規則 │ 專長 │ 職業 │ 物品 │ 種族 │ 附錄 ────────────── 🔍 Ctrl+K ─┐
├ 法師 │ 術士 │ 牧師 │ 德魯伊 │ 吟遊詩人 │ 武僧 │ Warlock │ ⋯ ────────┤
│                                                                      │
│  法師 ‧ 學派                                      ┌ 法師 ‧ 9 學派 ─┐  │
│  防護                                             │ 必備技能    1 │  │
│  5 條專長 · 難度 1–5 · 全數屬於「知識」判定          │ 防護        5 │  │
│  ┌──────────────────┐ ┌──────────────────┐        │ 咒法        5 │  │
│  │ 奧術防禦  難度1 知識│ │ 投射防禦  難度2 知識│        │ 塑能        5 │  │
│  │ 效果全文…          │ │ 效果全文…          │        │ ⋯            │  │
│  └──────────────────┘ └──────────────────┘        └───────────────┘  │
│  （學派依序往下捲，右側目錄可跳轉）                                      │
└──────────────────────────────────────────────────────────────────────┘
```

- **一篇連貫的章，往下捲。** 9 個學派依序排下來，每個學派是一個小節：
  學派名 → 描述 → 底下直接列出它的專長。讀得完整章，也能 Ctrl+F 一次找完。
- **專長卡兩欄。** 單欄時中文長行超過 90 字、掃讀吃力；兩欄把行長壓到約 40 字。
  卡片 `align-items: start`，高度各自撐開，不強制對齊。
- **右側小目錄**跟著捲動高亮目前所在小節，點擊跳轉。

### 專長卡的內容

預設顯示：名稱、難度徽章、分類 chip、**效果全文**。
點擊卡片就地展開，補上：

- **前置與後續** —— 這條需要什麼（含 `kind` 標籤，如「需 DM 裁定」），
  以及有哪些專長把它當前置。兩邊都可點擊跳轉。
- **來源** —— 工作表名與列號（`法師學派專精 R5 · C1`）。

**不顯示勘誤標記。** 勘誤是給規則書作者對帳用的，不是玩家讀規則時需要的資訊，
放在條目上只會製造雜訊。完整勘誤清單移到附錄章節，`errata` 表與
`docs/勘誤清單.md` 都不受影響。

**不顯示 CP 成本表。** `2^等級 × 難度` 是全書通則，不是每條專長各自的性質，
印在每一張卡上是重複 612 次同一條公式。改為附錄章節的獨立試算工具（見第五節）。

### 其他章節的差異

- **專長章節**：沒有學派，改以**分類**（戰鬥／運動／操作／感知／知識／交涉）分節。
- **職業章節**：`class_trait`（被動特性，不能用 CP 買）獨立成一節並標明
  「此為被動特性，無法以 CP 購買或升級」；Warlock 另有「魔能祈喚」一節。
- **物品章節**：詞綴卡多顯示部位與加值兌換階級；素材頁用父子版面
  （素材 → 其詞綴與 D100 區間）。
- **散文章節**（創角規則、附錄的世界觀等）：單欄，`section` / `subsection`
  兩層標題，右側目錄列 `section`。

## 三、全域搜尋：Ctrl+K 跳轉

搜尋不再佔據版面，改為 Ctrl+K（或點右上角）叫出的覆蓋層。

- 沿用現有查詢：**同時比對名稱與效果內文**，名稱命中排前面。
- 搜尋範圍從專長擴大到 `feat` / `class_trait` / `invocation` / `affix` /
  `material_affix` / `race` / `rule_text`，每一類結果標明它屬於哪一章哪一頁。
- 選中結果後**切換到該條目所在的章節與頁籤、捲動到它、短暫高亮**，
  而不是開一個獨立的結果頁。搜尋是導覽工具，不是另一種閱讀模式。

**位址模型**：每個條目有一個穩定位址 `{chapter, tab, anchor}`，
`anchor` 用資料庫 id。前置鏈跳轉、搜尋跳轉、右側目錄都走同一套。

## 四、視覺：兩套主題，一組變數

**羊皮紙暖白（預設）** 與 **燭光皮革（暗色）**，共用同一組色相（朱紅／古銅），
以 CSS 自訂屬性實作，切換只換變數值。

| 變數 | 羊皮紙暖白 | 燭光皮革 |
|---|---|---|
| `--bg` / `--bg2` | `#f8f2e2` / `#ece2c9` | `#191310` / `#100c0a` |
| `--card` / `--card-open` | `#fffdf4` / `#fffef8` | `#241c16` / `#2c231a` |
| `--line` / `--line2` | `#ddd0ae` / `#e6dcc3` | `#3e3327` / `#2b221a` |
| `--text` / `--text2` / `--text3` | `#2c2418` / `#55492f` / `#8b7b5b` | `#f5ecd8` / `#c6b494` / `#8b7c63` |
| `--accent` / `--accent-ink` | `#9a3b23` / `#fff8ec` | `#e0764f` / `#1b1209` |
| `--gold` / `--gold-ink` | `#8a6414` / `#fffaf0` | `#c9a227` / `#1b1209` |

**唯一需要分開設計的元件是難度徽章。** 深色底可以用燙金 `#c9a227`；
亮色底上金色對比不足，改用深青銅 `#8a6414` 配白字。強調色同理：
朱紅 `#9a3b23` 在深底上會沉掉，暗色版提亮為赤陶 `#e0764f`。

其餘皆為變數換值。主題選擇存在 `localStorage`，預設跟隨系統明暗。

**字體**：內文用無襯線（Noto Sans TC），標題與章節名用襯線（Noto Serif TC）
取得書卷感，但長段落一律無襯線 —— 中文襯線在螢幕上的可讀性不足以撐起大量內文。

## 五、CP 試算工具（附錄章節）

一頁式計算器，取代原本印在每張卡上的成本表：

- 輸入難度（或從專長清單挑一條）與目標等級 → 列出各級成本與累計
- 支援 `difficulty_scale = legend`（傳奇技能點，1 點 = 10 CP）
- 支援難度 `1or2` 這類需 DM 裁定的條目：讓使用者自己選 1 或 2

**公式放在 Rust（`src-tauri/src/rules.rs`），不放前端。**
理由是 Phase 4 的角色卡計算會用同一份，而且必須跟 `tools/rules.py` 對得起來。
新增 `cargo test` 以「法師範例」那張角色卡做回歸，與 `tools/validate.py`
用的是同一組基準值 —— 兩邊實作分歧時測試會抓到。

## 六、程式結構

現在的 `App.tsx` 是 408 行的單一檔案，塞進 6 個章節會失控。拆成：

```
src/
  App.tsx                  外殼：章節／頁籤狀態、主題、Ctrl+K 掛載
  api.ts                   Rust 指令的型別化包裝
  rules.ts                 只放顯示用的格式化（難度、分類），不放公式
  theme.css                兩套主題的 CSS 變數
  nav.ts                   位址模型 {chapter, tab, anchor} 與跳轉
  chapters/
    ClassChapter.tsx       職業（14 頁）
    FeatChapter.tsx        專長（6 頁）
    RaceChapter.tsx        種族
    ItemChapter.tsx        物品（詞綴／素材／價格表／分布）
    ProseChapter.tsx       散文（創角規則、附錄的世界觀等）
    AppendixChapter.tsx    附錄索引、對照表總覽、勘誤清單、CP 試算
  components/
    FeatCard.tsx           專長卡與就地展開
    SectionNav.tsx         右側小目錄（含捲動高亮）
    RefTableView.tsx       ref_table 的通用渲染
    CommandPalette.tsx     Ctrl+K
    ThemeToggle.tsx
```

每個 chapter 元件只負責「拿到自己那一章的資料並排版」，彼此不互相引用；
跨章跳轉一律透過 `nav.ts` 的位址模型，不直接呼叫對方。

### 後端（`src-tauri/src/db.rs`）

現有四個指令中，`search_feats` 與 `facets` 是為舊介面設計的，不再適用。
新的指令集：

| 指令 | 回傳 | 呼叫時機 |
|---|---|---|
| `toc` | 章節／頁籤樹與各頁條目數 | 啟動一次 |
| `class_chapter(class_name)` | 該職業的流派、專長、被動特性、祈喚 | 切到職業頁 |
| `feat_chapter(group)` | 該組專長，依分類分節 | 切到專長頁 |
| `race_chapter` / `item_chapter(kind)` / `prose_chapter(sheet)` | 對應章節資料 | 切頁時 |
| `ref_table(id)` | 單張對照表 | 需要時 |
| `entry_detail(kind, id)` | 展開區內容：前置鏈、後續、來源 | 點擊卡片 |
| `search(query)` | 跨型別結果，每筆帶 `{chapter, tab, anchor}` | Ctrl+K |
| `cp_table(difficulty, scale, max_level)` | 各級與累計成本 | 試算工具 |

`build_info` 保留。`db.rs` 已 621 行，一併依章節拆成
`db/mod.rs`、`db/class.rs`、`db/feat.rs`、`db/item.rs`、`db/prose.rs`、`db/search.rs`。

**測試策略不變**：`cargo test --lib` 直接跑在真正的 `dist/d100.db` 上。
每個新指令至少一個測試，驗的是「查詢能不能正確對付這份資料的形狀」——
例如 `class_chapter("Warlock")` 必須同時拿到 12 個契約、41 條專長與 58 條祈喚。

## 七、實作順序

這次改版順帶完成 `docs/PLAN.md` 裡 Phase 3 剩下的瀏覽頁項目
（種族、詞綴、素材、對照表、規則散文），因為章節骨架一旦立起來，
空著的頁籤比沒有頁籤更糟。分三階段，每階段結束時應用都是可跑的：

**階段 1 — 骨架與核心兩章**
`toc` / `class_chapter` / `feat_chapter` / `entry_detail` / `search`，
外殼、主題、Ctrl+K、職業章節、專長章節。
完成後舊介面即可整個移除。

**階段 2 — 其餘四章**
種族、物品、創角規則、附錄（含對照表總覽與勘誤清單）。

**階段 3 — CP 試算工具**
`rules.rs` 與其回歸測試、試算頁。

## 八、明確不做

- **不改資料庫、schema 或任何資料管線工具。** 這次只動 `app/`。
- **不做編輯功能。** 寫回 errata YAML 仍是後續項目，不在本次範圍。
- **不做版本比對頁。** 同上。
- **不在專長卡上做任何規則驗證。** 那是 Phase 4 建卡時的事。
- **不加第三方 UI 框架。** 現有相依只有 React 與 Tauri API，維持不變；
  主題、卡片、覆蓋層都用原生 CSS 寫得出來，引入元件庫只會讓視覺定制更難。
