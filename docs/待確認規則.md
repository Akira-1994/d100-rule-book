# 待確認的規則問題

`docs/勘誤清單.md` 記的是「某一列某一格的資料有問題」，由工具自動產生。
這份則是**規則層級**的疑問 —— 資料本身沒壞，但規則的定義不夠明確，
會直接影響 Phase 4 角色卡的計算結果。需要與規則書作者確認後才能定案。

---

## 1. 知識判定要進位還是無條件捨去？

「創角色須知」定義 `知識 =（INT＋WIS）×1.5`，
Patch note 1.1 第 6 條則說「所有擲骰結果（包含技能檢定、攻擊、傷害）
若有小數點，若大於等於 0.5 則一律進位」。

以「法師範例」那張角色卡驗算：

| 項目 | 公式 | 計算 | 範例卡上的值 |
|---|---|---|---|
| 戰鬥 | DEX+SKI+STR | 18+13+7 = **38** | 38 ✅ |
| 運動 | DEX+SKI+CON | 18+13+13 = **44** | 44 ✅ |
| 操作 | INT+SKI+WIS | 24+13+19 = **56** | 56 ✅ |
| 感知 | INT+RES+SPI | 24+24+13 = **61** | 61 ✅ |
| 交涉 | CHA+WIS+SPI | 13+19+13 = **45** | 45 ✅ |
| **知識** | (INT+WIS)×1.5 | (24+19)×1.5 = **64.5** | **64** ❌ |
| 抗毒素／抗控制／抗轉化／抗噴吐／抗魔法 | — | 37／43／48／42／48 | 全部相符 ✅ |
| 強韌／精神／靈魂 | CON×5／RES×5／SPI×5 | 65／100／65 | 全部相符 ✅ |

十六項衍生數值有十五項完全吻合，只有知識差 0.5。

**問題**：Patch 1.1 的進位規則只適用於擲骰結果，還是也適用於這種
建卡時就算好的衍生數值？範例卡寫 64，等於是無條件捨去。

**目前處理**：`tools/rules.py` 依 Patch 1.1 進位（算出 65），
`tools/validate.py` 會把這個差異報成警告，不會擋建置。

## 2. 詞綴的「部位」和角色卡的「裝備欄位」用的是兩套詞彙

詞綴表寫的是**物品種類**，角色卡寫的是**身體欄位**，兩者對不起來：

- 詞綴部位（16 種）：武器、魔導槍械、項鍊、法杖、鎧甲、戒指、頭環、
  手環、披風、盾牌、手套、鞋子、腰帶、主要裝備、武器(弓)、全
- 角色卡欄位（法師範例 P 欄，10 格）：頭、手、手臂、身體、披風、
  腰帶、鞋子、項鍊、戒指（左）、戒指（右）

「鎧甲」要戴在「身體」、「頭環」要戴在「頭」、「武器／盾牌」則根本
不在那十格裡（範例卡把它們放在「其他」欄）。

**問題**：Phase 4 要能檢核「這條詞綴可不可以附在這件裝備上」，
需要一張對應表。是否該由作者定義一份權威的欄位清單？
另外「主要裝備」和「全」的確切範圍是什麼？

**目前處理**：兩套詞彙各自原樣保存，尚未建立對應關係。

## 3. 難度 `1or2` 的語意

「基本專長」的〈知識〉（第 29 列）與〈語言〉（第 38 列）難度欄寫 `1or2`。

推測是因為這兩個是「元技能」—— 學哪一門知識／哪一種語言決定了難度。
若是如此，資料模型上它們應該是一個技能家族而不是單一條目。

**問題**：難度由什麼決定？是否應該列舉出各個知識領域與語言及其難度？

**目前處理**：`difficulty` 留 NULL、`difficulty_raw` 保存 `'1or2'`，
CP 成本暫時無法計算。

## 4. 「劇情取得」種族的 CP 處理

〈原初-星之幼體〉的 CP 調整欄寫「劇情取得」而非數字。

**問題**：這代表建卡時不能選、只能由 DM 在劇情中授予嗎？
若 DM 允許建卡時選用，CP 該怎麼算？

**目前處理**：`cp_cost` 留 NULL、`cp_raw` 保存原文。
Phase 4 預計在建卡精靈中隱藏此種族，並允許 DM 模式解鎖。

## 5. 傳奇技能點與 CP 是兩套計價單位

傳奇專長的難度欄有兩種寫法：`6（戰鬥）` 和 `傳1（知識）`。
依該表前言，「傳奇難度需消耗傳奇技能點，一點傳奇技能點需消耗 10 點 CP 兌換」。

**問題**：難度寫 `6` 的傳奇專長，是走一般的 `2^等級 × 6` CP 公式，
還是也要換成傳奇技能點？兩者混在同一張表裡但單位似乎不同。
另外傳奇技能點有取得上限嗎，還是純粹用 CP 無限兌換？

**目前處理**：新增 `feat.difficulty_scale` 欄位區分，`cp` 走一般公式、
`legend` 標記為傳奇技能點。目前 27 條傳奇專長中 19 條是 `cp`、8 條是 `legend`。

## 6. 術士的血脈技能沒有分類

「術士」整張工作表的 56 個條目都只有名稱、難度與效果，**沒有分類欄**，
名稱也沒有像法師學派專精那樣附上「（知識）」之類的註記。

其他職業表都有分類：牧師領域與德魯伊結社是交涉、武僧混用戰鬥／運動／感知、
Warlock 混用交涉／感知／戰鬥、賢者是知識。

**問題**：術士的血脈技能要用哪一種判定？
「施法者創角須知」提到術士的必備技能是「血脈呼喚（交涉）」，
推測血脈技能也走交涉，但那只是推測，整張表就這樣統一套下去風險太大。

**影響**：這 56 個條目在 Phase 4 無法歸入六大技能的任何一類，
角色卡上會沒有地方放，需要檢定時也不知道該加哪個數值。

**目前處理**：分類留空，`data/layout/術士.yaml` 以 `category_source: none`
明確宣告這張表沒有分類來源，驗證器改報一條彙總警告而非 56 條。

## 7. 尚未連結的前置條件

有 11 條前置條件目前標記為 `free`（只顯示、不驗證）：

- 跨職業施法要求：`同時具備奧術、神術及自然/詩歌施法能力`（5 條）——
  這是一句敘述而非可檢核的條件，需要作者定義「具備某種施法能力」的判準
- 指向尚未建模的能力：`驅散/斥喝`、`野性變身能力`、`詩歌施法能力`、
  `可由冥想升級`
- 語意不明：`生物的能力`、`???`

前置結構化率的演進：Tier A 完成 83%、Tier B 完成 94%（神語、詞綴賦予等接上）、
Tier C 完成 94%（167/178，新增 `path_level` 類別涵蓋德魯伊傳奇領域的
「該結社技能等級達4」）。剩下的 11 條多半不是資料缺漏，而是規則本身
寫成了敘述句，需要作者給出可檢核的定義。
